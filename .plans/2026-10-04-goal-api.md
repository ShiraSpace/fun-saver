| Route | Success | Error → answer |
|---|---|---|
| `POST …/goals` | `201` + the stored `Goal` | `ValidationError` (bad or malformed body; `jsonBody` gives `null`) → `badRequest(API_ERRORS.invalidGoal)` **400**; `GoalAlreadyActiveError` → `conflict(API_ERRORS.goalAlreadyActive)` **409**; not signed in **401**; not an editor **403** (wrapper); anything else rethrown → 500 |
| `DELETE …/goals/[goalId]` | `200` + the ended `Goal` (`ending: 'cancelled'`, `endedAt` set) | `GoalNotActiveError` (unknown, ended, or another account's id — one answer, rule 5, no `404`) → `conflict(API_ERRORS.goalNotActive)` **409**; **401**/**403** from the wrapper |

New error responses use `API_ERRORS`, never `error.message` (`src/lib` does not
import from `src/app/api`). The existing overdraft/validation answer on the
withdrawal route keeps `error.message` — untouched.

Commit: `feat(goal): set and cancel routes, and route params reach the handler`.

## Contract for PR 3 — `AccountSummary.goal`

```ts
export interface AccountSummary extends Account {
  wallets: WalletSummary[];
  goal?: Goal;
}
```

- **Present exactly when the account has an active goal** at page load (its
  `goals` row with no `ended_at`). An ended goal never appears, so on this field
  `endedAt` and `ending` are always `undefined`.
- **The key may be present with value `undefined`** (`{ ...account, wallets, goal }`).
  Test `account.goal`, never `'goal' in account`.
- `goal.id` — what the cancel route takes: `DELETE /api/accounts/${account.id}/goals/${goal.id}`.
- `goal.amount` — **agorot**, always whole shekels × 100 (1 … 100,000 ₪).
- `goal.name` — trimmed, 1–30 characters.
- `goal.picture` — `{ kind: 'emoji', emoji }` in v1; switch on `kind`, later
  versions add `{ kind: 'photo', url }`.
- `goal.startedAt` — ISO timestamp.
- **Reached is not on the summary.** Work it out with
  `goalReached(goal, savings.balance)`, where `savings = walletNamed(account.wallets, WALLET_NAMES.savings)`;
  that balance is settled by the same load, so it equals what the server's lock
  uses (spec rule 7).
- Carried on every page that builds summaries (home, `/method`, `/transactions`)
  and for accounts in child view too; showing it only in the parent view is
  PR 3's choice, not the data's.

## Decisions (approved 2026-10-04)

1. `addWithdrawal` uses `wallet.name === WALLET_NAMES.savings`; the wallet is
   already in hand, so no `walletNamed`.
2. No "deposits ignore the goal" test: `addDeposit` is untouched, so no break
   in this diff could redden it.
3. Viewer-gets-403 tests on both goal routes. Verified: the JSON store's
   `FileSession` reads the file from disk on every `read`/`write` (no cache),
   so a test can append `{ accountId, userId, role: 'viewer', addedAt }` to
   `accountUsers` in the temp store file after `createOwnedAccount`, and the
   route sees it. If that turns out clumsy in two files, it becomes a helper in
   `src/test-utils/`.
4. The four new `API_ERRORS` messages are English, as proposed.
